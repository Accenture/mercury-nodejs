## What happened

- **Design.** `src/otel/` (config / span / otlp / export / index), exported as the `otel` namespace. `bus.ts`'s
  `emitTrace` returns the dataset and `EventBus.forward` routes it to `distributed.trace.forwarder` through the
  registry's envelope router (`sendEvent` — a no-op when no function is registered there) WITHOUT a trace, so the
  forwarder's own execution emits no dataset; `execute` became an instance method for that. `Platform.run()` calls
  `activate(config, registry)` before announcing the routes. The exporter uses the runtime's `fetch` with
  `AbortSignal.timeout` (no session to close). Keys, defaults, mapping (exact W3C ids; a non-W3C dataset is skipped),
  retry (5 attempts, 1 s × 1.5ⁿ) and diagnostics mirror the Rust port. Deltas from the engines, documented:
  `otel.exporter.otlp.connect.timeout` has no effect (fetch has one overall timeout; a warning names it), scope
  `mercury-composable-nodejs`.
- **Tests** (`test/otel-forwarder.test.ts`, 17, node:test with a `node:http` decoding collector): the same matrix as
  the Python twin — headers, mapping, ISO-8601, wire-format round trip, partial success, diagnostics, endpoint
  validation, delivery + credential, retry to success, final rejection, refused connection, credential re-read per
  export, the switch, an application's own forwarder winning, a bad endpoint failing activation, the host hook end
  to end (one traced drop-n-forget execution → exactly one span at the collector).
- **Gates:** `npm test` (tsc build + 93 tests, 17 new) green; mkdocs strict OK.
