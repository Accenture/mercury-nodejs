## Context

The thread [[bp-rest-automation-nodejs]] named the two applications' hand-mounted routes as the first adopters once the
edge was in. Both mounted their HTTP surface through `Platform.addRoutes`: the main flow its reply page, wait and reply
endpoint, the agent-question app its configuration, replay, history, transcripts, click and the device's stream. This
session moved them onto `rest.yaml` entries served by [[rest-automation-nodejs]], the Node pack first; the Python twins
still mount theirs.

## What was done

- **`extensions/ask-person`:** `resources/rest.yaml` with four entries; the handlers became private functions
  (`ask.reply.config`, `ask.reply.page`, `ask.reply.wait`, `ask.reply`) taking `(headers, body)` and reading the
  `AsyncHttpRequest` map (the ticket from the path parameter, the bearer from the map's headers, the JSON body already
  parsed by the edge); `identify` takes the headers map; `attach` registers the functions on the platform's registry
  instead of mounting; `rest.automation: true` in its `application.yml`; README.
- **`extensions/agent-question`:** `resources/rest.yaml` with six entries; the same shape for the configuration, the
  replay and history, the transcripts and the click (`question.decide` validates the `{id}` parameter); the stream
  `question.events` is an interceptor behind `stream: true`: the head `text/event-stream` with a 120 s idle allowance,
  each row a `question` event through `EventStreamWriter.writeNamed`, a refusal the head's status with the JSON body
  and a close, a heartbeat `write(null)` every 25 s that the edge writes nothing for, `closeStreams` still ending every
  stream through the wake-ups; 200 instances. README.
- **The core (`src/event-stream.ts`):** a writer whose reply sink no longer takes a segment closes itself, so the
  stream producer stops when its device is gone (the engines' object stream fails a write to a closed stream); a
  test in `test/event-stream.test.ts`.
- **Tests:** both harnesses serve the extensions' `rest.yaml` on the default registry (`yaml.rest.automation` a
  `file:` location, `rest.automation` on); the stream test reads the edge's frames; the attach test checks the
  functions registered private; a 405 case added. README (the REST section names the first adopters), CHANGELOG
  Unreleased Changed.

## Decisions

- **Eric's:** the hand-mounted routes refactored onto `rest.yaml`.
- **Made here, as defaults without a ruling (listed on the thread):** the functions reply with the exact bytes they
  always sent, as text with a content type - a map body would be pretty-printed with its nulls omitted, and the
  React UI reads nulls (`outcome.status === null`); the SSE `id:` line is gone, since the UI keeps its cursor from
  the row's `seq` and ignores every event but `question`; identity stays inside the functions (an `authentication`
  entry would change the 401 body's shape and the reply endpoint's app-token rule); the entries' timeouts exceed
  `ask.engine.timeout` and `question.reply.timeout`; `Platform.addRoutes` stays in the host.
