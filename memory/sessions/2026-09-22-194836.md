## What happened

Eric's Dynatrace review of the v4.12.15 four-runtime certification traces found the span trees broken
on the engine side (an orphaned client leg, a lane span per relayed token, no span covering the HTTP
round trip). The engines now record the round trip as its own span (`service=http.request`,
mercury-composable and mercury `fix/connected-edge-spans`) and map only that record to SERVER. This pack's
forwarder adopts the same rule so a mixed-runtime trace renders one tree: `span kind = SERVER iff service ==
http.request`; every function execution — including the first one, whose `from` is `http.request` — is
INTERNAL. One line in the span mapper (`src/otel/span.ts`), the mapping docstring, the tests (a function execution encodes as
kind 1, the edge record as kind 2) and a CHANGELOG *Changed* entry under `Unreleased (4.12.15 in
preparation)`.
