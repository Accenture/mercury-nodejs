## What We Did

- **The rule (Eric's):** the configuration is resolved relative to the application file - the file `mercury-serve` is given
  (`path.resolve(args.app)`, the full path the command line names), or the script Node ran for an application that starts the
  platform itself (`process.argv[1]`) - and the working directory is never searched: the engines' classpath convention, the
  configuration travels with the application and does not depend on the launch directory. Before, the CLI searched the working
  directory first and the app's folder only as a fallback (so a stray `resources/` in the launch directory shadowed the app's
  own), and the lazy singleton probed the working directory alone.
- **Code (`36f18bc` on `fix/resources-next-to-the-application-file`, PR #113 OPEN):** `AppConfig(path, argv, appDir)` resolves
  `DEFAULT_CANDIDATES` under `appDir`, defaulting to `mainScriptDir()`; `loadConfig(path, appDir)`; the CLI passes
  `path.dirname(appPath)` - no probing loop; `resourcesDir` (beside an explicit file, else `<appDir>/resources`, undefined with
  neither) is where `log-context` looks for `app-log-context.yaml` (it used to fall back to the working directory's `resources/`);
  `source` is the absolute path found; `Platform.run` logs `Configuration: <source>`. An explicit `--config` file that does not
  exist is still refused by name.
- **Tests (201, +5):** next to the app; the working directory never searched (a decoy in cwd); the direct run anchored on
  `process.argv[1]`; an explicit file keeps its companions beside it; and two SUBPROCESS runs from a decoy working directory -
  `node app.mjs` and `node dist/src/cli.js app.mjs` (plus `--config`) - where the app writes its configuration to a file and exits
  before any function registers. tsc clean.
- **Verified by hand:** `node dist/src/cli.js examples/llm-helper/llm-helper.mjs -Drest.server.port=8092` from the repository
  root logs `Configuration: .../examples/llm-helper/resources/application.yml` and `/info` answers as `llm-helper`.
- **Docs:** README, `configuration-reference.md`, `config-logging-actuators.md`, both examples' `application.yml` comments and

## Decisions

- Script-relative only, no working-directory fallback (Eric: "it should not scan any directory"); the rare layout that relied on
  it passes `--config` or moves the folder (the CHANGELOG's upgrade note).
- `node -e` and a REPL have no script (`process.argv[1]` unset) and load nothing rather than probing cwd; `loadConfig(path)` is
  the explicit way.
- `source` becomes an absolute path; `resourcesDir` is the one folder companion files share with the configuration file.
