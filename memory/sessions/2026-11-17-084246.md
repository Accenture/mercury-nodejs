## What We Did

- **Why.** Building the transcript audit store (#126) showed that `AppConfig.get` returned a `-D` override as written, so
  `-Dkey='${POSTGRES_PASSWORD}'` would have sent the literal text; the helper's yml took the credential from the
  environment instead. Eric asked for the substitution in all four runtimes after the Node lockstep.
- **The change.** `src/config.ts`: an override's string value (a `-D` argument, or `appConfig().set`) goes through
  `substitute` like a file value - an environment variable with a default, or a reference to another configuration key,
  resolved at read time; a non-string override is returned as it is. `test/config.test.ts` "an override value resolves
  references like a file value" (a reference to a file key inside a URL, a default, an unresolved reference as undefined,
  the environment read at read time, a `set()` value). `npm test`: 499 tests, 434 passed, 0 failed, 65 skipped.
- **Record.** README (the configuration paragraph), CHANGELOG Unreleased Changed 1 (after the audit store's Added 1,
  merged by hand when the branch was rebased onto the #126 merge). The engines' twins: mercury-composable
  `feat/system-property-substitution`, mercury Increment 203; the Python pack's `feat/override-substitution`.

## Decisions

- A runtime override's value is resolved like a file value (Eric, 2026-11-17); the one compatibility edge, a `-D` value
  that relied on a literal `${...}`, is accepted - a file value never allowed it.
